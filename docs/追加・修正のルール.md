# 追加・修正のルール

このリポジトリは個人用です。大量の機能より、**探しやすい・理解しやすい・コピーしやすい**ことを優先します。

## 新しいコードを追加する場合

1. `rust/src/` 以下の分類にファイルを作り、`rust/src/lib.rs` で公開する。
2. 日本語コメントで用途、前提、計算量、境界条件を書く。
3. `#[cfg(test)]` のユニットテストを付ける。
4. `rust/README.md` とルートの一覧にリンクを追加する。
5. [学習状況](学習状況.md)の「コード」を更新する。ただし理解度は本人が確認した範囲だけ変更する。
6. `cd rust && cargo test && cargo fmt --check` で確認する。

## GitHubの記録方法

- **Issue**：次に追加したい機能、理解の不明点、バグなど。タイトルは日本語で具体的に。
- **PR**：複数ファイルにまたがる変更や、理由を残したいときに使用。無理にPRを作らない。
- **コミット**：日本語で何を変更したか書く（例：`累積和の空配列テストを追加`）。
- **Issueを閉じる**：実装・確認が終わったもの。実装があるだけでは「理解済み」にしない。

## ほかのコードを参考にした場合

- コードの出典URL、ライセンス、どこを参考にしたかを確認する。
- 既存コードを無条件に転載しない。
- AtCoderのコンテストに参加するときは、その時点の最新ルールも確認する。

## 既存の資料で済ませる場合

- 自作する前に [外部資料](外部資料.md) やRust標準ライブラリを確認する。
- 記事が十分なら解説・実装を重複して作らず、用途と注意だけ書いてリンクする。
- 他人のコードを貼り付ける場合はライセンス・出典・AtCoderの生成AIルールを確認する。
