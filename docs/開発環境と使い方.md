## 普段の作業イメージ

```text
atcoder/                     ← 作業ディレクトリの例（ac-test READMEの想定）
├── ac-test/                 ← localhost bridge、Tampermonkeyスクリプトを持つ別リポジトリ
├── abc467/                  ← cargo-competeで作成したコンテスト
│   ├── src/bin/a.rs
│   └── testcases/a.yml
└── abc468/
```

```sh
# 初回のみ: cargo-competeの公式手順で設定
cargo install cargo-compete --locked
cargo compete init  # 実際の対話入力・既存設定に従う。二重初期化しない

# コンテスト用ワークスペースで
cargo compete new abc467
cd abc467
cargo compete test a
cargo compete submit a
```

> 上記は**利用コマンドの参考例**で、現在のPCの `compete.toml` を取得して再現したものではない。設定ファイルや使用中のRust・crateのバージョンは、実機のコンテスト用ワークスペースを正本とする。 `cargo compete init` の引数と対話設定は [公式手順](https://github.com/qryxip/cargo-compete/blob/master/README-ja.md) に合わせる。

### ac-test と cargo-compete の役割分担

1. `ac-test` の配置例は、`ac-test` と `abc467` を同階層にする構成。
2. 別途 `ac-test` を `cargo run --release` で起動し、`ac-test.user.js` を Tampermonkey に登録する。
   - 現在のTampermonkey一覧には `AtCoder → cargo-compete testcase bridge` があるが、`ac-test.user.js` の `@name` は `ac-test`。**同じスクリプトか未確認**のため、二重導入しないよう [一覧の確認事項](Tampermonkeyスクリプト.md#自作ツール-ac-test-との関係) を参照する。
3. AtCoderの問題ページを開くと、表示中の問題文から収集できるサンプルと、対応可能な入力形式のみの境界値/stressケースを、`abc467/testcases/a.yml` に保存する。
4. `cargo compete test a` でサンプルと生成ケースを実行する。

**重要:** `generated-*` のケースは期待出力（`out`）を付けていない。正答判定ではなく、主にpanic、RE、TLEなどを見つけるためのテスト。複雑な入力形式は自動生成の対象外。詳細は [ac-testのREADME](https://github.com/rebuildup/ac-test#readme) を参照。

## 入力の3方式

**基本は今使っている`read_i()`・`read_vi()`・`read_s()`。** まずは[実際の書き方と短縮例](../rust/notes/入力と出力.md)を参照する。

| 優先 | 状況 | 選ぶ方法 |
| --- | --- | --- |
| **まず試す** | 整数・文字列・1行の整数列 | 既存の`read_*` スニペット |
| 入力が複雑 | AtCoderで配列・グラフ・`Usize1`などをまとめて読む | `proconio::input!`（依存設定がある環境） |
| **必要なときだけ** | クレート不可で、行をまたぐ可変長入力を読む | [汎用Scanner](../rust/templates/abc.rs) |

`read_vi()` が1回で読むのは1行だけ。配列が複数行に分かれる場合は、一括トークン読み取りが必要になることがある。ただしそれだけを理由に、普段の簡単な問題まで毎回Scannerに置き換える必要はない。

`read_s().into_bytes()` なら`String`変数を残さずバイト列が得られる。1行に2個の整数があるなら`let [a, b]: [i64; 2] = read_vi().try_into().unwrap();`と書ける。詳しい前提・別の書き方・Yes/No出力は[入力と出力](../rust/notes/入力と出力.md)へ。

- [proconioテンプレート](../rust/templates/proconio.rs)：AtCoder向けに短く書けるが必須ではない。
- [1行入力の実装例](../rust/templates/line_input.rs)：現在の書き方を保つ。
- [Scannerの実装例](../rust/templates/abc.rs)：必要なら参照する補助的な実装。

`cargo-compete` はコンテスト作成・テスト・提出、`ac-test` はサンプル・境界値テストの補助。いずれも入力の3方式と独立して使える。

## コンテスト開催中の注意

生成AIによるコード補完・デバッグ・解法の相談は ABC / ARC / AGC の開催中は禁止。使用済みコードの出典管理も必要。詳細は [AtCoderで使うときの注意](AtCoderで使うときの注意.md) と公式ルールを参照。
