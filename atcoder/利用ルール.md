# AtCoderで使うときの注意

最終確認日: **2026-10-30**。[AtCoder生成AI対策ルール（2026-10-14版）](https://info.atcoder.jp/entry/llm-rules-ja)を確認。**コンテストの開催時点の公式ルールが最優先**。

## 開催中にできること・できないこと

- ABC / ARC / AGC の開催中は、生成AIの使用が**原則禁止**。生成AIによるコード補完、解法相談、コード生成、バグ診断は利用しない。許容される例外（問題文の翻訳など）は公式ルールを参照する。
- コンテスト**開始前に生成AIで作成したコード**は、開始前にWeb上で公開し、作成時期を確認可能にしたうえで、**コピー使用時に参照URLを提出コードへ添付**すれば使用可能。
- 生成AIを使わずに第三者が書いたコードのコピーでは、AtCoderルール上の**出典表示は義務ではない**が、長いコードでは強く推奨される。**ライセンスの確認は別の義務**。
- これは開催中のABC / ARC / AGC向けの規則。過去問の練習には同じ開催中ルールは適用されず、AHCには別のルールがある。

## このキットのリンクと外部の出典を区別する

| コード・資料の由来 | 提出ソースの参照欄 |
| --- | --- |
| **コンテスト前に公開済みの`atcoder-kit`内のコード** | ヘッダーの**リポジトリへのリンク1つ**でよい。キット内の各関数に個別URLを並べる必要はない（公式ルールの例示） |
| **キット外で事前公開された生成AI製コードをコピー** | **そのコードの事前公開先URLを別途添付**。キットへのリンクだけではカバーされない |
| **非AI製の他者のコードをコピー** | 出典は義務ではないが、特に長いコードは記載を強く推奨。利用ライセンスは確認する |
| **記事・公式ドキュメントを読んだだけ** | 閲覧しただけで一律にコード出典の追記が必要になるわけではない。自分のメモや参照資料として残したい場合は`Notes / refs`を利用する |

公式ルールでは、公開済みGitHubライブラリを使う場合、**そのリポジトリへのリンクを提出ソースに含めれば、コードごとの個別リンクは不要**と説明されている。

## 署名付きRustテンプレート

[提出テンプレート](../rust/template.rs)は、`read<T>()` と空の`main()`がある[原本](../rust/templates/contest.rs)に、Actionsが短いヘッダーと末尾の`Notes / refs`を付けたもの。

```rust
// GH: rebuildup | AtCoder: rebuild | Data use: unrestricted
// github.com/rebuildup/atcoder-kit/tree/<公開済みコミットの先頭12桁>

// ... read<T>() と fn main() {}

// Notes / refs:
// -
```

- **ヘッダーのリポジトリリンク**：コンテスト前に公開されていたこのキットを示す。Actionsは`main`の公開済みコミットを参照してテンプレートを更新する。自身の生成コミットを参照する循環は避ける。現在のファイルに埋め込まれたリンクが**参加コンテストの開始前の版**を指すか確認する。
- **末尾の`Notes / refs`**：キット外からコピーしたコードの参照URLや、調べた記事・手動メモを必要に応じて記録する欄。ヘッダーのリンクの代用品ではない。
- **個別のキット内リンク**：追加する必要はないが、参照履歴を細かく残したい場合に記載してもよい。
- **ライセンス**：`Data use: unrestricted`はデータ使用方針の表示であって、標準ソフトウェアライセンスではない。

これらは暗号学的な署名ではない。**開催中に新しい生成AI製コードを作成・修正する用途に使わない**。
