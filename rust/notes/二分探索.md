# 二分探索：目的別に4つの書き方

探したいのは**境界**か、単に**存在するか**か。まずここを区別する。

昇順配列 `a = [1, 2, 2, 2, 4]`、探す値 `x = 2` なら、`x` 以上の最初の添字は **1**、`x` より大きい最初の添字は **4**。

| どんなとき | 使う形 |
| --- | --- |
| **実戦で一番短く境界を求める（標準API）** | `a.partition_point(|&v| v < x)` |
| **自前で最短に近く書きたい** | `while left < right` のループ |
| **仕組みを理解して改造したい** | 境界・更新条件をコメントしたループ |
| **関数として何度も呼びたい** | [既存の `lower_bound` / `upper_bound` 実装](../src/search/binary_search.rs) |

## 1. Rust標準APIで最短に書く

```rust
let lower = a.partition_point(|&v| v < x);  // x以上の最初の位置
let upper = a.partition_point(|&v| v <= x); // xより大きい最初の位置
```

`use` も外部クレートも不要。`partition_point` は先頭から「条件を満たす要素が連続する長さ」を返す。

**前提は `true, true, ..., false, false` と並ぶ判定条件**。この例では `v < x` が成り立つ要素が先頭に並ぶよう、`a` が昇順ソートされている必要がある。

`binary_search(&x)` もあるが、**重複要素の最初の位置は保証されない**。存在するか知りたいなら `a.binary_search(&x).is_ok()` が短い。

## 2. 標準の二分探索APIなしで、直接短く書く

```rust
let mut left = 0;
let mut right = a.len();
while left < right {
    let mid = left + (right - left) / 2;
    if a[mid] < x { left = mid + 1; } else { right = mid; }
}
// left が x 以上になる最初の添字（全て小さければ a.len()）
```

これが現在の `nibun` スニペットに近い形。`left + (right - left) / 2` は `left + right` の加算オーバーフローを避けられる。

## 3. 仕組みを説明し、条件を改造するための形

```rust
let mut left = 0;       // [0, left) は「まだ条件を満たさない」
let mut right = a.len(); // [right, n) は「条件を満たす」

while left < right {
    let mid = left + (right - left) / 2;
    if a[mid] < x {
        // mid は境界より左。次は mid + 1 以降だけ調べる
        left = mid + 1;
    } else {
        // mid も答えの候補。mid を残して左側を調べる
        right = mid;
    }
}
let boundary = left;
```

変更したいのは基本的に `a[mid] < x` の条件。例えば `a[mid] <= x` にすると、`x` より大きい最初の位置を探せる。

**条件が単調でない場合は二分探索できない。** また、このコードが返すのは**添字**なので `boundary == a.len()` も起こり得る。

## 4. 再利用する関数が必要なとき

自分で関数を呼びたいなら、すでに [`binary_search.rs`](../src/search/binary_search.rs) にテストつきの `lower_bound` / `upper_bound` がある。毎回コピーするより`partition_point`で十分なら、そちらを使う。

**方針:** 4種類を無理に暗記しない。「今は短さ」「仕組みを復習」「条件を変える」「汎用関数が必要」のどれかで選ぶ。
