# 実戦例：文字列に対する区間クエリ

実際に書いていたコードを基準に、**解法は変えず、書くための負担を減らす**ことを考える。Scannerや余分な抽象化には置き換えない。

## 元の考え方

- `s` の各位置から `t` が一致するか調べ、開始位置の一致回数を `prefix` に記録する。
- 1-indexedの区間 `[l, r]` を0-indexedへ変換し、その範囲内で `t` を置ける開始位置を調べる。
- `t` の長さを `m` とすると、最後の開始位置は `r - m + 1`。区間が `m` より短いときは `No`。
- この例では `m <= 10`、`n <= 4 * 10^5` なので、文字列比較を1位置で最大 `m` バイト行っても全体は `O(nm + q)`。

## 実際に使っていた入力の形

```rust
let q = read_i();
let s = read_s();
let t = read_s();

let sb = s.as_bytes();
let tb = t.as_bytes();

let n = sb.len();
let m = tb.len();
```

このコードでも十分動く。ここから**文字列として使わない `s` と `t` を残さない**なら:

```rust
let q = read_i();
let sb = read_s().into_bytes();
let tb = read_s().into_bytes();
let n = sb.len();
let m = tb.len();
```

`as_bytes()` 自体はコピーしない。ここでの利点は**中間変数が減ること**。

## 実戦で書き直すとしたら（入力と出力の部分だけ）

```rust
// read_i() / read_vi() / read_s() は既存スニペットから展開する。
// prefix を作る部分は、すでに書けているコードをそのまま使う。

fn ans(ok: bool) {
    println!("{}", if ok { "Yes" } else { "No" });
}

// main内
let q = read_i();
let sb = read_s().into_bytes();
let tb = read_s().into_bytes();

let n = sb.len();
let m = tb.len();
let mut prefix = vec![0usize; n + 1];

for i in 0..n {
    prefix[i + 1] = prefix[i];
    if i + m <= n && &sb[i..i + m] == tb.as_slice() {
        prefix[i + 1] += 1;
    }
}

for _ in 0..q {
    let lr = read_vi();
    let l = lr[0] as usize - 1;
    let r = lr[1] as usize - 1;

    let found = if r - l + 1 < m {
        false
    } else {
        let last = r - m + 1;
        prefix[last + 1] > prefix[l]
    };
    ans(found);
}
```

**上のコード片は `fn main()` の中身の例**（`fn ans` と `read_*` 定義は外側）。短いコードでも元のアルゴリズム・インデックスの意味が追えることを優先する。

## どこを省略して、どこは残すか

| 変更 | 良い点 | 注意 |
| --- | --- | --- |
| `read_s().into_bytes()` | `s` と `sb` の二重の変数を避けられる | Unicode文字数ではなくバイト長になる |
| `let [l, r]: [i64; 2] = read_vi().try_into().unwrap();` | 2値を直接束縛できる | 2個の入力が保証される必要がある。添字アクセスのほうが読みやすければそのまま |
| `ans(found)` | 毎回 `println!("Yes")` / `println!("No")` を書かずに済む | 使用が少ないなら `println!("{}", if found { ... } else { ... });` でよい |
| `prefix[last + 1] > prefix[l]` | 差を計算せずに有無を判定 | `prefix` が一致回数の累積で単調非減少という性質を使う |

無理に「最短コード」を目指して**条件や境界の意味が読めなくなるのは避ける**。

## 次にできる改善

- `q` と区間の型を `usize` に揃えるスニペットは便利か（今の `read_i()` と `read_vi()` は `i64`）
- 1行で2個・3個の変数を受け取るスニペットは実際に繰り返し使うか
- Yes/No の出力は関数にするよりエディタの `YES` / `NO` / `YN` 展開が速いか

これらは**実戦で試してから**スニペットを増やす。本文の具体例だけで十分なら新たなユーティリティ関数にしない。
