# Rustスニペット

**覚える数を抑えて、入力や出力の手間を減らす。** 展開結果を理解できることも大切にする。

## 使い分け

| 分類 | 対象 | 判断 |
| --- | --- | --- |
| **常用候補：6件** | `stdri`、`stdrvi`、`stdrs`、`ANS`、`YES`、`NO` | [最小セット](snippets/core.json)。入力の3件は実際の解答で使用を確認。出力の3件は希望に基づく**未検証の候補** |
| **条件付き：13件** | `proconio`、`input`、`inn`、`innm`、`innmk`、`invn`、`invnm`、`stdru`、`stdrvs`、`stdrvc`、`YN`、`nibun`、`ketawa` | 長い処理の省略や特定の環境で便利。いつも覚える必要はない |
| **まず直接書く：7件** | `repn`、`pi`、`pl`、`wordmatch`、`s2u`、`stdrb`、`stdr2` | 短い・重複する・使い方を参照すれば十分 |

**実際の使用回数の計測結果ではない。** 手元のエディタ設定は変更せず、従来の26件を[完全版](snippets/rust.json)に保持する。

## 常用候補：使い方を開く

| 接頭辞 | 展開するもの | 注意・参照 |
| --- | --- | --- |
| `stdri` | `fn read_i() -> i64` | [整数を1行読む](基礎/入出力.md#すぐ探す) |
| `stdrvi` | `fn read_vi() -> Vec<i64>` | [整数の配列・2値入力](基礎/入出力.md#1行で複数の値を受け取る)。一度に**1行**だけ |
| `stdrs` | `fn read_s() -> String` | [文字列・`into_bytes`](基礎/入出力.md#文字列を-as_bytes-せず受け取りたい)。`trim()` に注意 |
| `ANS` | `println!("{}", ans);` | [答えの出力](基礎/入出力.md#yes--no--答えの出力)。変数名を変更できる |
| `YES` | `println!("Yes");` | [Yes/No](基礎/入出力.md#yes--no--答えの出力) |
| `NO` | `println!("No");` | [Yes/No](基礎/入出力.md#yes--no--答えの出力) |

`stdri` などは**関数の定義を挿入するスニペット**。`read_i()` と呼ぶには、その関数が同じ提出コード内に必要。最小の[提出テンプレート](template.rs)には何も同梱せず、必要な関数だけ追加する。

## 増やす・減らす判断

1. **頻度:** 直近の問題で実際に何回使ったか。欲しいと思ったものは使用実績と区別する。
2. **操作コスト:** 直接打つより、接頭辞を思い出し、候補選択・展開・修正するほうが短いか。
3. **理解:** 展開内容と前提が分かり、問題に合わせて直せるか。

頻繁に使う・誤操作なく展開できるなら常用。たまに必要で長ければ条件付き。短い処理や用途を思い出せないものは**コード例のリンクだけ**でもよい。まず直近2〜3コンテストの実使用を確認してから、今の候補を確定させる。
