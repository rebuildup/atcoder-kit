# スライディングウィンドウ：固定長の区間和

**長さ `w` の連続区間の和を、開始位置を1つずつ動かして調べる**ときに使う。毎回 `w` 個を合計し直さず、左端を引いて新しい右端を足す。

## まず使う形（通常の配列）

```rust
// a: 数値の配列、1 <= w <= a.len()
let mut sum: i64 = a[..w].iter().sum();
let mut ans = sum;

for i in 0..a.len() - w {
    sum = sum - a[i] + a[i + w];
    ans = ans.min(sum);
}
// ans: 長さ w の連続区間の最小和
```

- 最初の区間は `[0, w)`。開始位置を `i` から `i + 1` に動かすと、**外れるのは `a[i]`、入るのは `a[i + w]`**。
- `a[..w]` は先頭から `w` 個のスライス。`iter().sum()` で初期値を作る。
- 最大和なら `ans.max(sum)`。固定長でなく、条件に応じて両端を伸縮させる「尺取り法」とは使い分ける。
- 計算量 `O(a.len())`、追加メモリ `O(1)`。要素や合計に負数があり得る場合は `i64` など符号付きで扱う。

## 円環（末尾から先頭へ戻る）

**配列の最後と最初がつながっている**ときは、追加する要素の添字を `% p` で折り返す。長さ `p` の配列 `c` に対して、`1 <= w <= p` とする。

```rust
let mut sum: u64 = c[..w].iter().sum();
let mut ans = sum;

for i in 0..p - 1 {
    sum = sum - c[i] + c[(i + w) % p];
    ans = ans.min(sum);
}
// 長さ w の区間の開始位置 0, 1, ..., p-1 をすべて調べる
```

- 通常の配列との違いは `(i + w) % p`。`i + w >= p` でも先頭に戻る。
- **最初の1区間を計算済みなので、更新は `p - 1` 回**。`0..p` にすると同じ区間をもう一度調べる。
- 引く値 `c[i]` は更新前の区間に含まれるため、非負コストなら `u64` の引き算でもアンダーフローしない。
- 計算量 `O(p)`、追加メモリ `O(1)`（配列 `c` 自体を除く）。

## 応用：周期ごとにまとめてから円環を調べる（ABC440 C）

[ABC440 C](https://atcoder.jp/contests/abc440/tasks/abc440_c) では色のパターンが `2W` 周期。**同じ余りのマスを先に集計する**と、長さ `2W` の円環配列から連続する `W` 個の最小和を求める問題になる。

```rust
// n, w は usize、提出テンプレートの read<T>() がある前提
let p = 2 * w;
let mut c = vec![0_u64; p];

// マス番号は1始まり。i % p が等しい位置のコストを集計
for i in 1..=n {
    c[i % p] += read::<u64>();
}

let mut sum: u64 = c[..w].iter().sum();
let mut ans = sum;
for i in 0..p - 1 {
    sum = sum - c[i] + c[(i + w) % p];
    ans = ans.min(sum);
}
println!("{}", ans);
```

- `n` は**元のマス数（入力個数）**、`p = 2 * w` は**周期（集計後の配列長）**。入力は `1..=n`、窓の移動は `0..p - 1`。
- この例では `w >= 1`、`p` が `usize` に収まり、コストの合計が `u64` に収まることが前提。`n < p` でも集計されない箇所が0になるため動く。
- 全体の計算量 `O(n + w)`、追加メモリ `O(w)`。各入力値が `u32` に収まっても、**合計は `u32` を超える**可能性がある。非負整数なので `u64` でよく、`i64` でもよい。
- `println!("{ans}")` は Rust 1.58 以降。古いコンパイラでは `println!("{}", ans)` を使う。ジャッジへの対応は[AtCoderの環境とツール](../../../atcoder/環境とツール.md)を参照。

## よくある間違い

- 初期和を `c[0] + c[n - 1]` とする：長さ `w` の区間にならない。`c[..w].iter().sum()` を使う。
- `c[i + 1]` を追加する：窓の長さを維持するなら `c[i + w]`（円環なら `c[(i + w) % p]`）を追加する。
- 集計後も `n` 回ずらす：円環の開始位置は `p` 通りであり、`n` とは別。

[累積和](累積和.md)は任意の区間和を何度も問い合わせるとき、こちらは**同じ長さの連続区間を順に走査するとき**に向いている。
