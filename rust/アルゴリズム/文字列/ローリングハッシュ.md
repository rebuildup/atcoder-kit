# ローリングハッシュ：部分文字列の高速比較

**同じ長さの部分文字列を何度も比較するとき**、先頭からのハッシュを前計算して各区間のハッシュを `O(1)` で取り出す。考え方は[累積和](../配列/累積和.md)に近いが、文字の順序を反映するために基数の累乗も使う。

## Rust：前処理と半開区間 `[l, r)`

```rust
const MOD: u64 = 1_000_000_007;
const BASE: u64 = 911_382_323;

struct RollingHash {
    hash: Vec<u64>,
    pow: Vec<u64>,
}

impl RollingHash {
    fn new(s: &[u8]) -> Self {
        let n = s.len();
        let mut hash = vec![0_u64; n + 1];
        let mut pow = vec![1_u64; n + 1];

        for i in 0..n {
            hash[i + 1] = (hash[i] * BASE + s[i] as u64 + 1) % MOD;
            pow[i + 1] = pow[i] * BASE % MOD;
        }
        Self { hash, pow }
    }

    fn get(&self, l: usize, r: usize) -> u64 {
        let left = self.hash[l] * self.pow[r - l] % MOD;
        (self.hash[r] + MOD - left) % MOD
    }
}

fn main() {
    let rh = RollingHash::new(b"abcabc");
    println!("{}", rh.get(0, 3) == rh.get(3, 6)); // true
    println!("{}", rh.get(0, 3) == rh.get(1, 4)); // false
}
```

- `hash[i]` は先頭から `i` **バイト分**の累積ハッシュ、`pow[i]` は `BASE^i mod MOD`。`hash[i + 1] = (hash[i] * BASE + s[i] + 1) mod MOD` で構築する。
- 区間 `[l, r)` は `(hash[r] - hash[l] * pow[r - l]) mod MOD`。`MOD` を加えてから引くことで `u64` のアンダーフローを防ぐ。
- `get(l, r)` は `0 <= l <= r <= s.len()` が前提。同じハッシュ設定（`BASE`・`MOD`）で計算した区間同士だけ比較する。
- 入力はバイト列 `&[u8]`。UTF-8の日本語などでは**文字番号ではなくバイト位置**になる。文字単位で比較したい場合は `char` 単位に変換するか、バイトの文字境界を管理する。
- これらの定数では中間乗算が `u64` に収まる。異なる定数を使うときはオーバーフローを再確認する。

## 衝突・計算量・使い分け

- **同じ文字列ならハッシュ値は一致**する。ただし**異なる文字列が一致する（衝突）可能性がある**。ハッシュ一致は完全一致の証明ではない。
- 衝突リスクを減らすには異なる法などでの二重ハッシュが使える。**厳密な一致が必要**ならバイト列を直接比較するなど、衝突しない方法を使う。
- 長さ `n` の前処理は時間 `O(n)`・追加メモリ `O(n)`、区間ハッシュの取得は `O(1)`、同じ長さの区間のハッシュ比較も `O(1)`。
- 比較する区間が少ない場合は通常の文字列比較で十分。ハッシュは大量の区間比較を効率化するための選択肢。
