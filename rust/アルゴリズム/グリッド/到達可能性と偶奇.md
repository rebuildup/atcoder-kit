# グリッドの到達可能性：最短距離と偶奇

**障害物のないマス目で毎秒必ず上下左右に1マス動くなら、最短距離だけでなく余った時間の偶奇も確認する。**

## 使うコード

ABC086 C「Traveling」のように、時刻と座標 `[t, x, y]` が順に与えられる場合の判定。

```rust
fn can_visit(prev: [i64; 3], next: [i64; 3]) -> bool {
    let dt = next[0] - prev[0];
    let dx = (next[1] - prev[1]).abs();
    let dy = (next[2] - prev[2]).abs();
    let dist = dx + dy;

    dist <= dt && (dt - dist) % 2 == 0
}
```

**スニペット：`gridvisit`**（[定義](../../snippets/rust.json)）。関数定義だけを展開する。`main()` と入力処理は追加しない。

時刻と座標は `[t, x, y]` の順番で渡す。単に距離を調べるときとは違い、**毎秒1歩動くことが必須**という前提がある。

## 入力からの利用例

[提出テンプレート](../../template.rs)の `read<T>()` を使う。時刻と座標は行をまたいでも3つの整数として読める。

```rust
fn main() {
    let n: usize = read();
    let mut prev = [0, 0, 0];

    for _ in 0..n {
        let next: [i64; 3] = [read(), read(), read()];

        if !can_visit(prev, next) {
            println!("No");
            return;
        }
        prev = next;
    }

    println!("Yes");
}
```

`can_visit` が一度でも `false` なら指定の順番で移動できない。次の予定を判定するときは、**直前の時刻と位置から**判定する。初期状態は `[0, 0, 0]`。

## なぜ偶奇の判定が必要か

最短距離（マンハッタン距離）は

```text
dist = |x2 - x1| + |y2 - y1|
```

使える時間は `dt = t2 - t1`。まず `dist <= dt` でないと届かない。

たとえば最短距離が1のとき：

| 使える時間 | 到達可能か | 理由 |
| --- | --- | --- |
| 1 | Yes | 最短の1歩 |
| 2 | No | 余った1歩を使って同じ場所に戻れない |
| 3 | Yes | 1歩で到着し、往復2歩を追加できる |

上下左右に1歩動くたび、`(x + y) % 2` で決まるマスの色が反転する。出発点と目的地の色の関係から、到着できる移動回数の偶奇は決まっている。

余分な時間は、隣のマスへの**行って戻る2歩**を何度でも加えて消費できる。したがって条件は次の2つ。

```rust
dist <= dt
(dt - dist) % 2 == 0
```

`&&` でつなげば両方を満たすか判定でき、`if { true } else { false }` は不要。

## 使える条件と計算量

- 障害物なし、上下左右に1歩ずつ移動できる（斜めは不可）。
- 1秒ごとに**必ず1歩**移動し、立ち止まれない。
- 各予定の時刻は前より後。座標や時間の差が `i64` に収まること。
- 障害物がある場合や、1秒待機できる場合には判定条件が変わる。待機できるなら、距離以下かどうかだけでよい。

`can_visit` は `O(1)`、`n` 個の予定を順に確認すると `O(n)`。予定の全件を保存する必要はなく、追加領域は `O(1)`。
