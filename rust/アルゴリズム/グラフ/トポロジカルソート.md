# トポロジカルソート：有向グラフの依存順序

**有向辺 `u → v` が「uより後にvを処理する」という制約**を表すとき、その制約をすべて守る順序を求める。閉路のない有向グラフ（DAG）でのみ可能で、**正しい順序は1通りとは限らない**。

## Kahn法：入次数0から処理する

`indeg[v]` は頂点`v`に**入る辺の本数（入次数）**。まだ処理していない頂点のうち入次数0のものをキューから取り出し、出る辺の行き先の入次数を減らす。

```rust
use std::collections::VecDeque;

fn main() {
    let g = vec![
        vec![2], // 0 → 2
        vec![2], // 1 → 2
        vec![3], // 2 → 3
        vec![],
    ];
    let n = g.len();
    let mut indeg = vec![0usize; n];
    for edges in &g {
        for &to in edges {
            indeg[to] += 1;
        }
    }

    let mut q = VecDeque::new();
    for v in 0..n {
        if indeg[v] == 0 {
            q.push_back(v);
        }
    }

    let mut order = Vec::new();
    while let Some(v) = q.pop_front() {
        order.push(v);
        for &to in &g[v] {
            indeg[to] -= 1;
            if indeg[to] == 0 {
                q.push_back(to);
            }
        }
    }

    if order.len() == n {
        println!("{order:?}"); // [0, 1, 2, 3]
    } else {
        println!("閉路があります");
    }
}
```

- 頂点0と1はともに入次数0なので、どちらを先に処理してもよい。`0 → 1 → 2 → 3`も`1 → 0 → 2 → 3`も有効。`1 → 2 → 0 → 3`は`0 → 2`に違反する。
- キューに入れるのは、**まだ処理していない前提がなくなった頂点**。入次数が0になった時点で追加する。キュー操作自体は既存の[VecDeque](../../基礎/VecDeque.md)を参照。
- `order.len() != n`なら、未処理の頂点が残っており、**有向閉路が存在する**（例：`0 → 1 → 0`）。閉路があると全頂点のトポロジカル順序は存在しない。
- `g[v]`は`v`から出る辺の行き先の一覧。[BFSの隣接リスト](BFS.md)と同じ形だが、BFSの距離計算とは目的が異なる。
- 各辺を一度ずつ調べるため時間`O(V + E)`。入次数・キュー・結果の追加メモリ`O(V)`（入力の隣接リストを除く）。頂点番号は`0..n`に収まるものとする。

最小の番号から優先するなど、**特定のトポロジカル順序**が必要な場合はキューを優先度付きキューに置き換える（計算量は変わる）。
