# 全探索：全列挙・bit全探索・再帰

候補を漏れなく調べる。**何を1つの候補とみなすか**に応じて、ループ・ビットマスク・順列・再帰を使い分ける。

## 2つの添字を選ぶ（全列挙）

```rust
let a = [2, 5, 7];
let mut count = 0;
for i in 0..a.len() {
    for j in i + 1..a.len() {
        if a[i] + a[j] == 7 {
            count += 1;
        }
    }
}
// count = 1（2 + 5）
```

- `i < j` にすれば、同じ添字を2回選ばず、順序だけ違う組も重複しない。
- すべての組を調べるので時間 `O(n²)`、追加メモリ `O(1)`。

## 選ぶ・選ばない（bit全探索）

`n` 個の各要素を選ぶかどうかは `2^n` 通り。各部分集合を `0..(1usize << n)` の整数（ビットマスク）で表す。

```rust
let a = [1, 2, 3];
let mut count = 0;
for mask in 0..(1usize << a.len()) {
    let mut sum = 0;
    for i in 0..a.len() {
        if (mask >> i) & 1 == 1 {
            sum += a[i];
        }
    }
    if sum == 3 {
        count += 1;
    }
}
// count = 2（{3} と {1, 2}）
```

- `mask` の `i` 番目が1なら `a[i]` を選ぶ。何も選ばない集合も含む。
- この例は各候補の合計計算に `O(n)` かかるので、全体で `O(n × 2^n)`。
- `usize` のビット幅以上のシフトはできない（`n < usize::BITS` を前提）。実際にはそれより小さい `n` でも計算量が厳しくなる。
- 基本的なビット操作は[ビット操作](../基礎/ビット操作.md)を参照。

## 選択を順に分岐する（再帰）

再帰では、現在の位置 `i` で「選ばない」「選ぶ」の2方向に進み、最後に条件を判定する。

```rust
fn count_subsets(a: &[i64], i: usize, sum: i64, target: i64) -> usize {
    if i == a.len() {
        return if sum == target { 1 } else { 0 };
    }
    count_subsets(a, i + 1, sum, target)
        + count_subsets(a, i + 1, sum + a[i], target)
}

let a = [1_i64, 2, 3];
let count = count_subsets(&a, 0, 0, 3); // 2
```

- すべての選択を試すなら時間 `O(2^n)`、再帰の深さによる追加メモリ `O(n)`。
- 途中の状態によって次の候補が変わるときも再帰が使える。**枝刈り**は、打ち切った先に正解がないと証明できる条件だけで行う。

## 並べる順番をすべて試す（順列全探索）

`n` 個の異なる要素の並び方は `n!` 通り。実装は既存の[順列（next_permutation）](順列.md#全順列を列挙するには先に昇順にソートする)を参照。**最初に昇順にソートしてから** `next_permutation()` を繰り返す。コードをこのページに重複収録しない。

## 選び方

| 調べる候補 | まず使う方法 |
| --- | --- |
| 異なる添字の2要素・3要素 | 多重 `for` |
| 各要素を使う・使わない | bit全探索 |
| 全順序 | [順列全探索](順列.md) |
| 選択途中の状態に応じて分岐 | 再帰（必要なら枝刈り） |

候補数が制約内に収まることを先に見積もる。探索そのものを高速化できない場合は、条件や計算を工夫して候補数を減らす。
