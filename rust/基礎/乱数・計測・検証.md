# 乱数・計測・検証：rand・Instant・assert

乱数生成・経過時間の計測・条件の検証をRustで行うときの書き方をまとめる。

## 乱数（rand）

Rust標準ライブラリには乱数生成APIがない。`rand` クレート0.9系の書き方：

```rust
use rand::Rng;

let mut rng = rand::rng();
let x = rng.random_range(1..=6); // 1〜6のいずれか
```

- `1..=6` は6を含み、`1..6` は6を含まない。結果は実行ごとに異なり得る。
- [AtCoderの2025年10月版言語一覧](https://img.atcoder.jp/file/language-update/2025-10/language-list.html)では `rand 0.9.2` が利用可能だった。これは**当時の情報**であり、今参加するコンテストの使用可能バージョンを保証しない。ローカルでは問題用 `Cargo.toml` に対応する依存（例：当該版なら `rand = "0.9.2"`）が必要。`atcoder-kit` 自体への追加は不要。
- 古い `rand 0.8` 系の `thread_rng()` / `gen_range()` と0.9系の `rng()` / `random_range()` を混同しない。

## 経過時間の計測（Instant）

```rust
use std::time::Instant;

let start = Instant::now();
// 計測したい処理
let elapsed_ms = start.elapsed().as_millis();
eprintln!("{elapsed_ms} ms");
```

- `Instant` は開始時点からの**経過時間**を測る。CPU使用時間を直接計測するものではない。
- `eprintln!` は標準エラー出力なので、ジャッジの解答用標準出力に混ざらない。

## 条件の検証（assert）

```rust
let a = [3, 5, 7];
assert!(a.len() == 3);
assert_eq!(a[1], 5);
assert_ne!(a[0], 5);
```

- 条件違反ならパニックする。`assert!` / `assert_eq!` / `assert_ne!` はリリースビルドでも実行される。
- `debug_assert!` は通常リリースビルドでは無効になる。コンテスト提出時の処理時間を考慮し、目的に応じて使い分ける。
