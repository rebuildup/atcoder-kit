# 入出力：read<T>()をそのまま使う

**提出テンプレートに `read<T>()` を標準搭載する。** 標準ライブラリのみで動作し、空白・改行・タブを区切りとして1トークンずつ読み取る。

## 整数・文字列

```rust
let n: usize = read();
let x: i64 = read();
let s: String = read();
```

型が推論できるなら `read()`、明示するなら `read::<i64>()` と書く。

## 文字列操作

```rust
let mut s = String::from("aあ");
s.push('b');                 // "aあb"
let bytes = s.len();         // 5（UTF-8のバイト数）
let chars = s.chars().count(); // 3（Unicodeスカラー値の数）
let ok = s.contains("あ");   // true
let prefix = s.starts_with("a"); // true
```

- `String` は所有する変更可能な文字列、`&str` は文字列スライス。`push(char)` は1文字、`push_str(&str)` は文字列を追加。
- `len()` は**文字数ではなくバイト数**。`chars()` はUnicodeスカラー値単位で扱うため、結合文字を含む場合の見た目の文字数とは異なる。
- `String` は `s[0]` のように整数で添字アクセスできない。ASCIIだけを扱うなら `s.as_bytes()` / `s.into_bytes()` でバイト列を参照・取得する。後者は `s` を消費する。
- 下記の提出用 `read<T>()` はASCIIトークン専用。日本語をその関数経由で正しく読み込むことはできない。

## n個の整数を配列へ

```rust
let n: usize = read();
let a: Vec<i64> = (0..n).map(|_| read()).collect();
```

`read()` はトークンを**1個だけ**読む。`Vec<i64>` は `FromStr` を実装していないため、`read::<Vec<i64>>()` では読めない。配列が複数行に分かれていても動作する。

## 文字列をバイト列で扱う

```rust
let s = read::<String>().into_bytes();
```

ASCII文字を添字で扱うときの形。文字列の末尾を判定するなら `let s: String = read();` のまま `ends_with()` を使える（[末尾からの文字列分割](../アルゴリズム/文字列/末尾からの分割.md)を参照）。

## 出力

```rust
println!("{x}");
println!("{}", if ok { "Yes" } else { "No" });
println!("{}", d.len());
```

`ANS` は変数、`pl` は式、`YN` はYes/Noのスニペット。単純な1行はそのまま書いてもよい。

## テンプレートの定義

[提出テンプレート原本](../templates/contest.rs)には次の短い関数を組み込む。署名付きの[提出ファイル](../template.rs)はGitHub Actionsで再生成する。

```rust
use std::io::*;
fn read<T:std::str::FromStr>()->T{
stdin().lock().bytes().map(|b|b.unwrap() as char).skip_while(|c|c.is_whitespace()).take_while(|c|!c.is_whitespace()).collect::<String>().parse().ok().unwrap()
}
```

- 1バイトずつ取り、空白を飛ばして文字列を作り、`FromStr` で指定した型に変換する。`stdin().lock()` は1トークンの読取中だけロックする。
- **ASCIIトークン専用**。`u8 as char` で処理するので日本語などのUTF-8文字列には対応しない。
- トークン不足・型変換失敗時はパニックする。入力が正しいことが保証されるコンテスト向け。
- **提出ソースのバイト数を優先**した選択。バイトごとの読み取りが多いので、大量入力では[Scanner](../templates/abc.rs)や `proconio` などに切り替える。

旧来の `read_i()` / `read_vi()` / `read_s()` は過去のコード用スニペットとして残す。標準の `read<T>()` と旧来の行読み取りを混在させない。
